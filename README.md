##### About me
##### Hi, <!-- you are watching cold fusion TV--> <!-- Like and subscribe PLEASE -->
<br>
For general questions or requests, email <b>iaindonaldnet@gmail.com</b> with <b>"[code]"</b> in the subject line.  
<br><br>
I make utilities and code libraries for <a href="https://www.freebsd.org/">FreeBSD</a>, Linux<sub><a href="https://alpinelinux.org/downloads/">Alpine :)</a></sub>, and microcontrollers. Computer hardware is usually capable of far more than our software realizes. 
<br><br>
UNIX utilities are building blocks. Their code libraries are easily linked, their I/O with pipes, their interface via stdout and stdin. Should libraries, apps, features require another 500 MB download for yet another environment when it's already running on the ultimate sandbox that is any operating system? Should its security rely on hardware components, secrecy, or anything beyond the OS memory management? Or does convenience require these environments? I don't think it needs to! We forget the work of art already there, and the philosophy that already brought computing to everyone. 
<br><br>
I am learning to define and improve the correctness of my software. To avoid the modern philosophy of trust in zero-trust. To manage state, error handling, all vectors of interaction for security then for finding efficiency. Hopefully you find it easy to read, and efficient where you use it. I can guarantee the variables will not be a single letter. <b>Feel free to steal it, but I encourage you to try and understand it as well. It can be improved. </b>
<br><br>
I have studied computer science since 2012 using Visual Studio Express. I'm best using languages C, Zig, Java, C#, and Kotlin, have experience in frameworks such as ASP.NET, Android JNI, and Express, related concepts including database and ODM strategies, and enjoy learning strategies for error disccovery and handling.
